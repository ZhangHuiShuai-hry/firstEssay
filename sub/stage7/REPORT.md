# 阶段7：CG上界引导的按需资源档查询

## 实际完成

基线23aa68df，独立新增sub/stage7，实现上一阶段的按需查询设计。demand_profiles.py调用已审计整线CG取得列池和界来源，建立完整档表，在乐观整数DP路径上选择未知档求精确MILP。verify7.py独立重建来源/档表，用另一个整数主问题逐步核对路径最优值及最终上下界；小规模再枚举所有档。原物理模型不变，不加RL，不改原x分支。

证明条件见DESIGN.md。未查询档保留有效UB或+∞；真实代表才贡献LB。CG完整Phase II价格给仿射UB，经济初始化MILP Best Bound给常数UB，两者逐档取min；所有新精确档结果继续收紧。最后整数DP上界与原CG有效UB取min，实际整数见证验证后才检查闭合。该算法是CG界+资源档MILP+整数DP，不是纯根CG或原x B&P。

## 收益与尚未解决的问题

1. **查询减少，整数闭环成立。** 强耦合例精确档查询24→14、48→34/35、72→56；无需全档扫描即可证明原整数最优。原20初始化就闭合，按需法没有查询。
2. **少查询没有带来稳定提速。** 小PP很便宜，前置CG加上反复计算/验证组合界抵消了减少的MILP调用。强耦合例按需法比全档DP略慢，仍慢于Compact。不能仅按调用数宣称加速。
3. **原40仍有关键上界瓶颈。** 前置CG耗时6.001秒，仅提供经济初始化常数UB136.9451+186.9510=323.8961，没有完整Phase II定价仿射界。查询开始前，整数DP重组CG已生成列就在6.082秒取得305.83，优于该次CG记录的LB304.63。后续18档查询耗时10.875秒，既未进一步改善LB，也未降低最终DP/全局UB323.8961。有限UB来自前置CG经济界，不能归功于查询收紧；利润改善来自已有列池的整数重组，不能归功于后续查询。
4. **固定预算切换不理想。** 原40单线定价困难，过早停止CG后查询同样困难的精确档，未解决根界收敛。原根CG对照的UB323.6813还略好；Compact在相同预算也得到同样利润且UB更好。没有整体优势。

详细CG/查询秒数、查询数量与总档数见evidence/paired20/profiles.json；逐次结果和源码/输入/证据SHA见各worker目录。全量日志及未查询档都保留。
