# sub 第一轮实验结论

日期：2026-11-04。基线为 `a2d3d86c`，独立分支 `codex/sub-line-decomposition`。本轮只新增 `sub/` 文件，未修改原模型及原求解器。

## 1. 回答研究问题

**建议继续研究整线方案列，暂不删原物理约束。** 它直接解决了工作站列之间重复任务、缺前驱、缺必做和回收不兼容的问题。整线列组合后仅剩 H/R 资源协调。本轮发现保留全部约束时比直接 Compact 更早证明最优的实例，以及在相同预算下 LB 更高/UB 更紧的实例。

但收益的主要来源是线间弱资源耦合下独立求解单线 MILP。大多数原始/结构组无需进入 CG 主循环，不能据此声称已经证明“CG迭代本身在大规模普遍优于CPLEX”。资源真正收紧时，三组整线CG都成功组合整数解，但均慢于直接 Compact。

## 2. 实际实现与数学语义

整线列包含该线全部站点、任务选择与模式，保持全部原节拍、疲劳、AND前缀、唯一性、必拆、回收及精确配置逻辑。主问题仅保留每线恰选一个方案和两类共享容量。单线定价是原单线 MILP 的资源对偶调价目标。初始化不使用全局 Compact warm start 或生成器构造见证。

局部域有列后，Phase I 对两类共享容量使用弹性变量；完整精确定价的负上界才能证明节点LP不可行。Phase II 使用全部原利润。每轮定价重新构造 MILP；所有列和整数方案都经过数据级检查及原Compact约束检查。受限IP不可行不代表原问题不可行。

理论关系为 `原Compact-IP = 整线Full-IP ≤ 整线Full-LP ≤ 工作站Full-LP ≤ Compact-LP`。详见设计文件。没有实现整线 B&P；当前只有全局上下界闭合时才能证明原整数最优。没有闭合时明确保留Gap。

V2另保存初始化单线经济目标的有效MIP Best Bound之和；该界可在单线超时后仍用于全局UB。它不依赖RMP对偶，不把截断PP incumbent当检验数上界，也没有启用截断定价继续CG。所有界都是求解器浮点容差下的数值证书。

**本轮不建议删除疲劳、必做、最低回收或AND来改善论文结果。** AND确实让40任务单线PP显著变难，但取消它会改变拆卸问题。优先研究保留AND的单线定价、资源档多样性和整数方案恢复。

## 7. 瓶颈归因

非重叠算法层统计满足：`PP_total + master_total + other_algorithm = wall_seconds`。`PP_total`再分Python建模、求解API区间、原始约束核验；原生优化是API区间的子项，不能重复相加。逐例数据在 `evidence/analysis_final/profiles.json`。

已有40任务原模型：算法12.377秒，PP总12.303秒，其中原生优化11.457秒；没有进入RMP/价格协调。该次慢的主要原因是两次单线整数优化，不是主问题或证书写盘。压缩JSON持久化只有毫秒量级，完整工作站证书另存SQLite。

2线seed12：算法8.780秒，单线原生优化8.337秒，独立经济最优方案资源兼容后闭合整数界。4线三seed均在独立线最优初始化后闭合。**这些成功首先证明分解利用了弱耦合，不证明反复CG迭代的加速。**

资源2/2例：算法1.550秒，PP总1.351秒、主问题总0.196秒，余项0.003秒；已有真正迭代，但单线PP及其模型/核验仍占主导。下一步应先优化这一部分和资源档补列，而不是优先压缩证书或加入RL。

## 8. 时间、失败与限制

首轮pilot_v1使用0.5秒收尾预留。三种40任务方法分别超15秒约0.343、0.259、0.967秒，全部保留并标记不及时；不用它们作严格预算胜负。V2统一2秒预留后，51/51运行都在15秒名义预算内完成，watchdog没有触发。Windows及native调用仍只能承诺测量到的软截止结果，不能声称硬实时保证。

全套共63次运行、60次预算内，3次超预算来自旧pilot；无硬停止、无求解器异常。最初重放脚本因相对路径格式化报错，修复为绝对路径后重放63/63通过；失败原因保存在 `evidence/execution_issues.json`。历史输出从未覆盖或删除。

CPLEX直接方法未接incumbent callback，首次求解器发现整数解时间未知；保存的是返回后首次独立验证时间。不能与整线分阶段的首次LB时间当成等价的搜索发现时间。时间仍受Windows负载、缓存和单次采样影响，没有做统计置信区间。

本轮最大规模40总任务，没有运行120/150任务。尚未验证一般整线LP非整数而受限IP无法闭合时的完整B&P；当前根算法遇到这种情况必须报告未证明。没有承诺任何实例都能得到可行解或最优解。

## 9. 下一步建议

1. 保留当前原问题，把整线方案列作为主候选分解，扩大少量固定种子验证并重复计时，确认本轮正面案例的稳定性。
2. 在AND和资源确实活动的实例上，研究单线PP的持久化建模、有效warm start，以及可验证的(H,R)预算补列；分开计量初始独立线求解与CG协调。
3. 构造和验证整线LP有正整数间隙/缺非支持资源档的例子，再决定是否接入现有原x分支B&P。不要把根CG池最优泛化成全局整数最优。
4. 目前不建议开始RL。当前较大原实例的成本主要是两次昂贵初始化，迭代次数不足以建立有说服力的学习辅助定价基准。先获得稳定、精确、确实需要多轮协调的求解基线。

总体状态：数学与本轮验证 **PASS（限定上述作用域）**；整数兼容结构改善 **PASS**；部分实例性能信号 **PASS**；“广泛大规模优于Compact”的科研主张 **PARTIAL，证据不足**。
