# 根节点诊断与整数方案获取

本轮完成根节点实验机制和有限诊断，不宣称已获得优于Compact的算法。原MILP、工作站列定义、精确定价和数值政策未改变。未引入RL。现有V0–V3及B&P入口保持可用；新增机制先在独立根节点入口验证，尚未接入整棵B&P搜索树。

## 实现及数学边界

`code/dwcg/root_diagnostics.py` 调用已验证的V2节点求解器，比较三组：

|组|初始整数LB|根列池|中途整数恢复|
|---|---|---|---|
|baseline|短时间Compact验证方案|空列|无|
|seed|相同获取政策|空列+已验证方案逐站配置|无|
|recover|相同获取政策|同seed|Phase II第1轮、每10轮及LP收敛轮|

初始Compact预算0.75秒，受限IP单次0.5秒。额外两次关闭Compact获取，用生成列自身求整数方案，每5轮恢复。每条witness均经独立数据级检查和原Compact约束验证。每个块加入整数方案的一列后，以这些列各取权重1即可得到无人工的根主问题可行解。因此注列保证Phase I存在零人工解，但不保证减少Phase II轮数。

受限IP使用真实利润及全部全局约束，人工变量不进入恢复。MIP时间截断只要有经过验证的整数解就可更新LB；受限IP不可行仅说明当前列池不能组合出整数解。生成列的LP目标不作为整数LB，受限IP最优不作为原IP最优。根UB仍仅来自原节点完整精确定价。只有验证整数利润与安全UB在原容差内闭合才签发整数最优标志。本轮根实验没有替代B&P。

诊断记录逐轮人工违约类型、目标、修复UB、检验数、对偶L1变化、列数、分数x数、正λ数、时间/疲劳容量余量、人机资源及回收余量、收益与各项成本。完整原始证书继续保存schema4 SQLite。`verify_root.py`对全部证据重新计算原始/对偶算术、检验数、覆盖及witness；小规模进一步通过独立全列枚举验证定价最优值。中等规模PP最优性仍依赖求解器证明元数据，不冒称独立枚举认证。

## 实验政策与限制

全部读取`code/data`冻结原始字节，保存实例和SHA，CPLEX单线程seed11、原NumericPolicy。5/6任务每臂10秒，20/40总任务每臂15秒软预算。预算包括获取解、根模型、精确定价、整数恢复、验证、逐轮落盘。最终结果落盘另记E2E；不包含Python启动/导入，不采用外部watchdog，不是Task03.1b严格端到端公平实验协议。实际可超过软时限，不能按本表宣称公平加速。

`pilot`保存16臂原始探索结果。其40任务运行期间曾与一次20任务无Compact诊断交叠，因此不能作为干净时间对照，全部保留。`serial_n40`随后无其他求解任务并发重新运行4臂，正式40任务诊断采用此组。`no_compact_tasks040`在串行复验完成后单独运行。仅单seed、单次观察，未运行更大规模或RL。

20任务三组均证明根LP最优，Compact证明原整数最优；根实验保留整数Gap，不误报最优。40任务四组均time_limit。5任务根LP27、整数24；6任务根LP59.38、整数56.63，根实验不负责闭合这两个整数Gap。原B&P回归继续证明这些整数最优值。

关闭Compact后，20任务受限IP依次为：第1轮不可行，第5轮116.67，第10轮129.42，最终第13轮131.12；每次已有解的受限IP均证明其自身最优。最终根LP137.865714，含16个分数x。这直接说明：生成列能够获得整数方案，但最终池整数最优131.12低于Compact最优132.58，当前列池没有覆盖达到原最优所需的整数配置组合。该运行曾与探索pilot交叠，其时间不用于公平比较。

关闭Compact的40任务单独运行中，第1/5/10/15/20/25轮的受限IP全部证明当前池整数不可行；根LP仍可行，15秒到时没有整数LB，有效UB332.751234。这是明确失败记录，不把原问题判不可行。说明现阶段缺少可组合整数列是实质性问题，不能将无LB仅归因于没有调用整数恢复。

## 对解的解释

40任务串行recover在第1/10/20/30轮受限IP均证明当前池最优300.03，没有改善初始解；最后仍有未完成定价，不能把第30轮结论外推到全部最终列或原模型。

最终RMP分数x：baseline175、seed196、recover188；seed/recover的相邻Phase II轮次有18次目标变动小于1e-7。根尚未收敛时已经出现显著平台与分数混合，下一步应研究配置多样性、对偶稳定化/多列生成，而不能简单增加受限IP调用次数。平台证据不独自证明某种稳定化一定有效。

整数方案成本比较（相同回收收益542.73）：

|项|根recover方案|Compact方案|
|---|---:|---:|
|直接执行成本|170.70|173.30|
|工作站成本|36|36|
|人工配置成本|12|12|
|机器人配置成本|24|16|
|净利润|300.03|305.43|

两者都启用6个站，Compact少配置2个机器人，节约8，执行成本增加2.6，净改善5.4。利润差来自模式与配置组合，不能解释为漏拆高收益任务。初始方案人工/机器人资源尚余8/5，回收要求两线超出19/29；Compact余量分别8/7及19/29。当前单例没有证据支持优先删除资源或回收约束。活动人工站的疲劳约束均有正余量，但离散可行域可能仍受其限制，不能据此宣布疲劳约束冗余。
