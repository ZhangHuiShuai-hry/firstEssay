# 本批实验的解释范围

本阶段验证根节点候选/认证控制，不增加分支树，也没有资源档位DP后处理。exact为同一实验引擎关闭候选功能的对照，仍有历史证明筛选；不能把它直接等同于sub既有完整生产链，也不与历史Compact时间拼接作新优势结论。

每配置一次，全部输入属于已观察开发实例。求解时使用原生warm状态，候选目标改变可能影响CPLEX后续搜索状态。减少认证轮数、减少调用、候选时间短均不能独自证明整体提速。一次较快结果不能支持统计显著性或规模泛化。

候选轮没有新列时立即原价认证；候选成功后，下一轮先解RMP与受限IP，若已有真实LB与有效UB闭合可直接安全结束。否则强制认证。认证出现未证PP时，仍继承旧引擎安全停止该次CG的规则，保留有效历史界和候选成果；可能在总预算尚未耗尽时返回time_limit（含局部PP截断），不能解释为一定用完全部60秒。尚未实现对截断认证继续调度或一般非零价格Best Bound上界。

候选20%和单线2秒均为软预算，原生非抢占调用、建模与验证可能略超；记录实际candidate_seconds，不截断统计数值。算法时间包含会话初始化、优化、列验证、整数恢复及释放。accounting.json中的end_to_end_seconds测量solve加最终结果持久化，开始于输入/源码冻结之后，不包含Python进程启动、模块导入及此前清单生成；不能称严格全进程E2E。这一开发微预算协议不替代后续外部worker/watchdog公平实验。

数学证书为浮点求解器容差下的证书。小例由完整独立枚举核对最大RC、完整LP/IP；中例重放检查原数据、主对偶、历史证明、候选与原价RC、覆盖及witness，完整局部最优性仍信任CPLEX原生最优状态。严格持久化入口verify_bundle.py补充源码SHA与native101/目标/Best Bound契约检查；audit.py主要负责数学重放，不能单独代表全部文件完整性检查。

本批尚无学习模型，未使用最终最优值、未来列、生成器构造见证决定动作。后续若训练，应按新完整实例划分训练/验证/最终测试，已有开发种子不能重新标成未见测试。
