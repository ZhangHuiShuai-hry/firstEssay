# 在线候选找列与认证回退：预设协议

首阶段输入为既有开发小例，完整列Oracle通过后运行80任务4线seed32、120任务6线ratio80 seed32/34。均属于开发数据，不是未见测试集。四策略：exact（只做原价认证）、short_raw（短预算原价找列）、fixed（α=.25价格混合）、adaptive（首次候选轮α=.25，以后α=1）。三种候选策略最多连续一轮成功候选轮，下一轮强制原价认证；无新正RC列则同轮立即原价认证。

候选价格为α当前RMP资源价格+(1−α)历史最小完整认证修复界所对应的价格，无历史则参考0。PhaseI不变；候选PP经济目标σ=0，每线最多2秒，累计候选调用总墙钟软上限为算法预算20%，剩余时间由余下线平分，预算不足时停止。每条候选列独立原域验证，按当前原始RMP价格与凸性对偶重算raw RC，只加入新的正RC列。任何候选轮均不用于构造上界，即使原生PP已证最优也不冒充原价定价终止证书；原生精确候选证明可进入同域历史缓存。

认证沿用reuse_v1已审计原价精确定价/缓存筛选，只有完整覆盖各线的认证轮才更新修复界或判断LP最优。候选轮找不到列不代表完整域无列。PhaseI不可行/全局整数最优仍使用原证据标准。受限IP witness始终独立原约束核验，候选成功后下一RMP再作整数恢复。

四种策略相同输入字节、warm原生逐线会话、单线程seed11、gap0、原NumericPolicy、短经济初始化.5秒、整数恢复.5秒。中例每worker60秒软算法预算，最终持久化单列时间，不宣称外部硬实时保证。候选开销、失败及超时均计入；轮换策略顺序，串行运行。每配置一次，作用是机制准入，不作显著性或泛化结论。未启动Compact新对照、训练或大规模组合。

进入中例条件：小例完整枚举LP/IP、每条候选RC和域检查、证书离线重放、伪证拒绝通过。中例完成后比较LB/UB/Gap、证明状态、候选和认证耗时、原生调用与列数。结果不佳则保留并分析，不修改本批预设规则或阈值。
