# 证明复用首阶段：完成情况与研究决策

实际实现可审计历史证明缓存、逐轮轨迹筛选、独立在线筛选入口和扩展证书验证器。原数学模型、sub与已封存RL资料保持不变。尚未实现下一阶段的启发式找列/认证切换，尚未训练学习策略。

## 结果与判断

10个既有开发输入、196个PhaseII定价块：10个可被此前精确定价证明排除，占调用5.10%；对应历史原生时间9.4793秒/703.1975秒，约1.35%。筛选全部查询约0.0774秒。6个阶段12正式输入均没有可免调用；收益集中在强资源竞争seed32/33。不能把历史时间直接当作可实现在线加速，因为跳过求解会改变CPLEX重优化状态。

在线关闭/开启筛选，5个实例各运行一次，共10次，另有gap小例1次：

- tiny5：两版均证明24最优，无跳过。
- tiny6：两版均证明56.63最优，无跳过。
- LP可行/IP不可行小例：两版均仅证明LP最优，上界4、无整数LB；复用PP从6降至4。完整列Oracle证实IP不可行，但生产算法没有搜索树，因此没有提升为整数不可行证明。
- 80任务4线seed32：均证明583.64最优；对照19.2046秒、复用20.4793秒，无跳过。没有提速。
- 120任务6线ratio80 seed32：均证明927.46最优；对照32.9675秒、复用30.3090秒，原生PP36→33。复用界927.46000003是向上数值余量累计，仍在原有全局容差内。单次差异不支持稳定提速结论，也不能将全部时间差归因于免调用。
- 额外gap小例：完整列LP6.5、IP2；生产返回LB2/UB6.5，正确保留整数未证明。

完整原值、实际PP事件分项、收尾时间见RESULTS.md与evidence/metrics.json。不与历史Compact软预算结果拼接成新的公平性能比较。

## 复现和限制

Python3.10.11、CPLEX22.1.1、单线程seed11、gap0，旧NumericPolicy不变。batch.py串行运行；原数据直接冻结复制，不重新生成，不读取构造见证。新格式reuse-screen-1区别原生精确与上界认证；旧验证器保持原入口，新格式用audit_online.py。源码复制来源和数学推导见DESIGN.md。

定价对象通过显式接口注入，旧引擎中的pricing_strategy/timing字段反映被绕过的工厂；实际PP策略为persistent warm，原生日志与pricing_native_events完整保留，正确计时在metrics.json按事件重算。该字段兼容性局限不能用来报告虚假的零PP耗时。软算法预算及最终写盘独立accounting，不是硬实时协议。证书复用不等同于有理算术认证；中例完整PP最优性仍以可信原生求解状态为边界。
