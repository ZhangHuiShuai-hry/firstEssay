# CG-V2：原生CPLEX持久化定价模型复用实验

## 研究范围与版本冻结

V1使用原生增量RMP与原PuLP精确定价；V2保留完全相同的增量RMP，只替换PP实现。`CG_V1_FROZEN.json`指向本轮开始时的完整源码及V1两轮实验数据备份，快照manifest包含源代码和全部数据文件的SHA256。现有结果不覆盖。新运行要求输出目录不存在，每次保存执行源码、输入、配置、启动时间和哈希。

不实现RL、启发式定价、Branch-and-Price或整数解补充算法。本轮全部结果仅针对DW根LP，不声称证明原问题整数最优。

## 数学一致性

每个工作站惰性初始化一个原生MILP，初始化计入根预算。变量为原有任务—模式选择与u/h/r，约束仍是每任务至多一个模式、节拍、u/h/r与实际模式使用的双向一致性，以及线性化累计疲劳上限。没有额外加入跨站优先、必拆、全局资源或最低回收约束。

每轮只更新对偶相关的线性目标。Phase I不计任务利润及站点/配置费用；Phase II恢复这些真实利润成本。两阶段均保留任务唯一性、回收、前缀优先和全局资源的对偶项。工作站凸组合对偶为常数项，不能遗漏。

为对齐PuLP实际传给CPLEX的表示，V2使用[0,1]有界整数变量（逻辑上仍为二进制），变量名及顺序、行顺序与原PP一致；凸组合常数在CPLEX外加回目标、检验数和界。这样避免改变求解器内部的目标平移表示。相对/绝对MIP Gap均为0，只接受原生状态101；时限或状态102均不冒充精确定价最优。每个返回列仍调用原make_column验证局部可行性，并由原独立列系数函数重算检验数。

## 正确性门槛

1. 真实CPLEX下比较V1/V2的矩阵、变量界、目标系数及常数。
2. 随机对偶、两阶段及反复切换，与原PP和完整枚举独立比较最大检验数。
3. 原始单/双线小例继续完整列枚举与最终终止证书验证。
4. 保留迭代上限、Phase I不可行/不确定、LP可行而整数不可行、恒零目标以及过期deadline测试。
5. 正式对偶重放选择已保存V1的完整历史：20/30任务seed11取120秒结果，40任务seed11取300秒收敛结果。重放其中每一个有完整定价的轮次、每一个工作站，不抽取方便的调用；先后次序按调用交替。比较V1、V2以及原日志的检验数，容差1e-5，允许不同但等价的最优列。

重放每臂单次调用最多60秒，未证明最优必须标记失败/未完成，不进入“全部检验数通过”的结果。重放输出逐调用CSV、完整对偶快照、求解器日志和输入/源历史哈希。它只代表三个完整历史，不代表全部大例的完整列枚举。

第一轮原生表示预检查保存于pricing_replay_01，中途为对齐PuLP的原生变量类型/常数表示而停止，不混入正式性能统计；正式重放使用pricing_replay_02及其通过标记。

## 端到端实验

- 两线，每线20/30/40任务，种子11/21/31/41/51。
- 120秒与300秒分别进行完整V1/V2配对，共60次根CG运行；两档预算独立统计。
- 使用原生成器及相同JSON输入，单线程CPLEX22.1.1、solver seed11、确定性parallel=1、默认预处理/算法、原始/对偶容差1e-8、整数容差1e-7、CG epsilon/可行性容差1e-7。
- 相同V1增量RMP，advance=1；PP不主动添加MIP start、不改变CPLEX的默认启发式/预处理设置。持久对象可能自动利用既有解或状态，这是需要测量的复用效应，不承诺会减少原生整数优化时间。
- 正式端到端所有工作进程固定`PYTHONHASHSEED=11`，仅通过子进程环境传递，不修改全局环境。原因是原稀疏系数函数遍历集合，未固定哈希会引入浮点累加/稀疏项顺序变化，并可能影响退化轨迹。该控制不修改RMP源码或数学模型。未控制哈希的`persistent_pp_120_01`保留为中断预试验，不混入正式`persistent_pp_120_02`与`persistent_pp_300_02`。没有把预试验差异断言全部归因于哈希。
- 每对版本按实例交替先后次序，各臂独立进程、串行运行，不并行启动其他求解器性能作业。
- 预算包含初始化、目标更新、模型构造、API转换、求解、读回和在线核查；共同CPLEX模块导入与最终报告序列化不计时。时限按剩余墙钟传给求解器，少量返回开销超出按实测保存，不裁剪数据。
- 若300秒后仍有双方截断，最多选少量代表例追加600秒，独立配置与目录，不替代原截断结果。

600秒补充的预定选择规则由select_pricing_hard.py执行：仅在两版均于300秒超时的配对中，按任务数降序、实例种子升序选最多一例。保存所有候选及选择理由；若无符合条件者则不追加。该单例诊断不混入五种子的主要成功率或加速统计。

## 状态、上下界与统计

已证明最优RMP目标是完整列LP的可行下界；完整精确定价轮次的对偶修复值是其有效上界。分别取已求解Phase II RMP目标最大值、完整定价上界最小值。部分工作站定价失败的轮次不产生上界。最终LP目标仅在CG证明收敛时填写；上下界与最终gap可以在截断时保留，绝不当作整数上下界。

全部已收敛版本/预算之间逐实例核对LP目标（1e-5）；截断界不得排斥另一个版本已证明的最优值。双方完成才计算精确速度比，一方截断只报告下界，双方截断不计算完成时间比。保留所有超时和异常，单独报告收敛率。

## 非重叠计时

PP完整时间内部划分：Python结构构造、原生模型创建/插入、PuLP到CPLEX完整转换、目标更新、原生整数优化及剩余读回/检查等。V1的目标构造包含在每次模型构造中；V2结构与原生创建只在首次访问工作站发生，目标更新每次记录。V2没有完整PuLP转换，但原生创建不是零成本。

根时间=RMP构造/更新+RMP接口+PP完整调用+其他；原生RMP时间是RMP接口子区间，不能重复相加。Phase I/II为另一种划分，也不叠加进组件时间。报告PP调用耗时的均值/中位数、原生求解与建模转换构成；调用之间依赖于同一CG轨迹，统计为描述性分析，不当作独立随机实验做显著性检验。

## 运行

```powershell
experiments/.venv/Scripts/python.exe -m unittest discover -s experiments -p test_persistent_pricing.py -v
experiments/.venv/Scripts/python.exe experiments/replay_pricing.py --out experiments/runs/my_pp_replay
experiments/.venv/Scripts/python.exe experiments/compare_pricing.py --config experiments/configs/persistent_pp_120.json --out experiments/runs/my_pp_120
experiments/.venv/Scripts/python.exe experiments/compare_pricing.py --config experiments/configs/persistent_pp_300.json --out experiments/runs/my_pp_300
```

不修改全局环境或安装。使用项目既有Python3.10虚拟环境及原solver_backend加载本机匹配版本的CPLEX API。旧CBC及V1源码接口不变。
