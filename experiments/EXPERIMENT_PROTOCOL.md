# ML-HRC-DLBP-CF 标准列生成实验协议

## 研究对象和声明边界

仅研究现有确定性 MILP 和工作站配置列的两阶段标准 CG。PP 为精确 MILP；不加入启发式、强化学习、分支定价、模型恢复或新的约束。完整列 IP 与紧凑 IP 等价；最大化时 IP ≤ DW-LP ≤ Compact-LP。CG 收敛只证明根节点完整列 LP 最优。受限列整数恢复不能一般性证明原 IP 最优或不可行。

## 已有材料及版本保护

实际源码位于 `code/milp` 和 `code/dwcg`；早期实验包位于 `code/experiments/dwcgTest/dlbp_experiment_kit`。早期包中的 SciPy 整数试算不能作为本项目 CG 运行结果；其 reference_double 是单线复制，两条线的整数利润 42，与本项目原始 two_lines 的 24 是不同数据。

工作目录没有 Git 仓库，故不虚构提交号。首次修改前保存 `snapshots/` 中的源码和 SHA-256。每次 run 独立冻结全部 Python 源码、配置、输入、环境、包版本、源码哈希及 UTC 起止时间。旧输出不覆盖，目录已存在时批量运行器报错。

## 环境和求解器公平性

主要实验使用项目 `.venv` 的 Python 3.10，以匹配本地 CPLEX 22.1.1 API。Python 3.12 下可继续使用 CBC，但不能加载本地只支持 3.8/3.9/3.10 的 API。进程内添加 CPLEX API 搜索目录和 DLL 搜索目录，不修改系统 PATH、注册表或全局 Python 包。直接 API 和 PuLP CPLEX_PY 的实际 LP/MILP 测试包括非零检验数；CPLEX_CMD 只做备用接口探测，正式实验用 CPLEX_PY。

单线程、CPLEX 确定性 parallel=1、随机种子 11、相对及绝对 MIP gap=0、原始/对偶容差 1e-8、整数容差 1e-7。预处理保留求解器默认并记录软件版本，不声称两种求解器预处理完全相同。CBC 同样一线程、两个随机种子 11、gap=0，保留兼容。CPLEX 的 tolerance-optimal、超时有解、超时无解和 infeasible_or_unbounded 不得简单映射成已证最优或不可行。

正式实验顺序运行，每项在独立 Python 进程内；精确 PP 若未证明最优则中断 CG，不接受当前候选作为最优定价。根节点有独立墙钟 deadline，PP/RMP 时间上限还取剩余预算。父进程提供最终进程树超时保护。超时或异常保留阶段检查点、已有基线和 solver 日志，不补造目标或最优性证书。

## 算例生成

所有新算例为合成基准，不是工业数据或经生理校准的安全标准。先按随机种子生成全局任务参数，再分线。每三项任务的构造模式依次偏向 H/R/J；额外模式按 sparse/mixed/rich 概率 .15/.55/1 生成，保证任务模式集合异质性。

H 时间为 2–4；R 时间为 H 时间的 .8–1.25 倍四舍五入；J 时间为 H 时间的 .5–.8 倍。模式成本分别为 1.8tH、1.2tR+1.5、1.5tJ+2。构造 H 任务的疲劳负荷为 .10–.15，其他任务的 H 备选负荷为 .28–.48；J 负荷为 .08–.13；β=d/t，R 的 β=0。约 80% 任务在构造模式成本上具有 6–18 的正回收余量，约 20% 的余量为 -1 至 -5。该依赖结构是可检验的实验假设，不能声称代表真实协作收益分布。

权重 1–4；必拆约为每线任务的前 20%（至少一个），最低回收为总权重的 35% 向上取整。任务按拓扑序分配到站点，所有任务组成一个显式见证；优先边只从较小拓扑序到较大拓扑序，全部为 AND。layered 图使用距离≤6的前向边，概率 .12；dense 概率 .22；chain 为完整链。记录边数和以 n(n-1)/2 为分母的前向边密度。

普通规模组固定节拍 15，每站构造至多三项任务；固定总量组节拍 20，标准 60-task/20-station 设计每站至多四项。构造见证检查局部节拍/疲劳/模式、前缀优先和资源数量；实验仍独立求解紧凑 MILP 验证其实际可行性。生成错误直接报错，不静默丢弃；所有未解与不可行实例保留。

## 三阶段与分组

阶段 A：原始单/双线、5 个种子的小单线、一个小双线和计划不可行控制；CBC/CBC、CPLEX/CPLEX、CPLEX-RMP/CBC-PP、CBC-RMP/CPLEX-PP 四种组合。全部调用完整列枚举与最终证书验证，比较目标、整数等价及 LP 界。退化下不要求不同求解器选择相同列或具有相同迭代数。

阶段 B 正式计划（`planned_BC.json`，尚须预算批准后的逐步运行）：

- B1：每线 n=10/20/30/40/50，L=2；其他生成规则固定。
- B2a：每线 n=10，L=1/2/3/5，总规模随线数增长。
- B2b：总任务 60，总站点 20，总人机预算均为 ceil(.8×20)=16，L=1/2/3/5；全局任务参数多重集完全不变。跨线不得保留原先跨区边，因此比较中仍存在优先图分块和回收/必拆分摊变化；记录边密度，不能声称彻底隔离所有因素。
- B3：F=.40/.60/.80，同一 seed 的全部其他输入不变。
- B4：先计算全任务见证所需 H/R；充足用 ceil(1.25×需求)，中等用原需求，紧缺用 floor(.8×需求)，上限不超过总站点。它是明确的需求参考而非最小资源需求；紧缺组可能不可行，必须报告。

种子为 11/21/31/41/51，每个处理 5 个随机实例。不同因子组复用的共同控制输入不作为额外独立样本，不跨组混算样本量。首轮 pilot 使用 n=6/10、L=1/2、固定总任务12/总站点4，B3/B4各三水平；完整 B 计划不视为已运行。

阶段 C：在 B 的实际规模结果上研究 PP 耗时随 n、模式数、疲劳和图结构的变化。当前只形成 pilot 瓶颈诊断，不声称完成正式 C。后续 mode/profile、graph/profile 采用配对参数设计；不预设 RL 优势。

## 基线与预算

1. Compact IP：记录 native 状态、最优/未证最优、可行利润、best bound、相对 gap、时间。
2. Compact LP：同一紧凑模型仅放松整数域，记录最优 LP 值及时间。
3. CG 根节点：只计算完整列 LP；根时间不含整数恢复或枚举验证。
4. Restricted IP：在已生成列上求整数模型；native 最优仅指受限模型。即使与 LP 界偶合也不把这一模块描述为 Branch-and-Price。

pilot 预算：IP 10秒、LP 10秒、根 CG 30秒、单次 RMP/PP 10秒、恢复10秒，父进程90秒。阶段 A 预算见其配置。完整 B/C 的预设上界为每作业600秒，必须先从低规模运行估计，而不是一次性启动全部125个作业。预算上界不是平均耗时预测。相同确定性设置的重复测量只估计运行噪声，不增加独立算例数。

## 时间口径

wall-clock 使用 perf_counter。根时间分为互不重叠的 RMP Python构造、RMP solve接口、PP完整调用、其他；Phase I/II 是另一套分割，不能与前述组件一起相加。PP完整调用包含 PP构造、PuLP→CPLEX转换、原生优化和读回/日志等开销。后处理单独给出原生优化、转换及其他开销，不再累加到已有根时间。CPLEX直接测量 solve 调用墙钟；CBC日志内部时间精度较粗，不能用于毫秒级结论。恢复、验证、进程导入和图表生成均单独计时或明确排除。
